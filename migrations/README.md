# Миграции базы данных

## Очередь оценок (2026-11-16)

Эта миграция обязательна перед запуском версии приложения из ветки
`fix/scheduler-rating-integrity`.

1. Остановить контейнер бота, оставив PostgreSQL запущенным:
   `docker compose stop bot`
2. Сделать резервную копию:
   `docker compose exec -T db pg_dump -U poputchik -d poputchik > backup_before_rating_migration.sql`
3. Выполнить миграцию из корня репозитория:
   `docker compose exec -T db psql -v ON_ERROR_STOP=1 -U poputchik -d poputchik < migrations/2026_11_16_rating_queue.sql`
4. Убедиться, что команда завершилась с кодом 0 и вывела `COMMIT`.
5. Только после этого запускать новую версию бота.

Миграция:
- переносит старые `pending_ratings.trip_id` в правильный `booking_id`;
- восстанавливает отправителя как `from_user_id`;
- проверяет, что все старые запросы сопоставлены;
- останавливается, если найдены несопоставленные или дублирующиеся оценки;
- сохраняет старые `trip_id` и `from_user_vk_id` как nullable legacy-поля, не удаляя их;
- добавляет ограничения уникальности, предотвращающие повторные оценки.

Если миграция останавливается с ошибкой preflight, не удаляйте строки вручную и не запускайте новую версию бота. Сохраните текст ошибки и резервную копию, затем отдельно разберите проблемные строки.
